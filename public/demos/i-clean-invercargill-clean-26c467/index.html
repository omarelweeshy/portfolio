3. Scope

From what is publicly visible, only the homepage seems affected. A file-level check on the server is still worth doing, because injected code sometimes hides elsewhere.

4. Cleanup and hardening checklist

  1. Find and remove the injected block from the homepage (template, widget or database content), and work out how it got in (for example an old plugin or a reused password) so the way in is closed.
  2. Update your CMS (e.g. WordPress), its plugins and theme to the latest versions, and delete any plugin or theme you no longer use.
  3. Rotate every admin password (CMS, hosting, FTP/SFTP and database), and remove admin accounts you do not recognise.
  4. Turn on 2FA (two-factor authentication) for all admin logins and for your hosting account.
  5. Request a Google Search Console review: check "Security issues", ask Google to re-crawl the homepage, and request a review if a warning was raised.
  6. Keep a backup and watch for repeats: take a clean backup and re-check the homepage source after a week.
